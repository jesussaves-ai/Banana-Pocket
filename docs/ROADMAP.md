# BananaOS Roadmap (RPC / SM4450)
Refs: `docs/RPC-PORT.md` (port log), `docs/RPC-TEST.md` (hardware checklist).

## Completed Baseline (0.4.9+)
- **Core & CI:** End-to-end QEMU `virt` boot/update/test (`tools/qemu-boot.sh`), A/B OTA updates, first-time setup, `ksmbd`, `dropbear`, `ath10k_snoc`.
- **Input & Library:** `rsinput` Nintendo layout (`A=east, B=south`). Single-screen RetroArch library only (no DS/3DS dual-screen launchers).
- **Display & Graphics:** 90°-rotated 1240x1080 panel in `banana-ui`; games run upright via `cage` (`video_rotation = 0`, Wayland context; requires `SEATD_VTBOUND=0` so `bananad` `SIGSTOP` on suspend never deadlocks VT switch). Mesa Freedreno GL + **Turnip Vulkan** enabled on Adreno `a613` (SwanStation 60fps @ 5x).
- **Hardware Validation (`docs/RPC-TEST.md`):** In progress on physical units.

## Next (Active Targets)
- [ ] **Plug-in vibration (starts 0.4.46):** the bolt and "Charging" notice work on 0.4.45, but the 300 ms pulse on cable-in did not fire (the edge never reached the motor, or the motor was opened and closed too fast for the effect to stick). `bananad` now holds the PMIC `pm8xxx_vib_ffmemless` FF input open for its lifetime, uploads the `FF_RUMBLE` effect once and reuses it, plays and stops it without blocking the main loop (a `vib_off_at` deadline, not a `sleep_us`), logs `charger plugged in/unplugged` on the edge and every failure inside `vibrate()`, and answers an explicit `touch /run/banana/vibrate` trigger. **To confirm on the unit:** replug and read `grep bananad /run/banana/messages` for `charger plugged in` then no `no FF input`/`play failed`; `sleep_skip = vib` suppresses the buzz to tell the edge from the motor.
- [ ] **Sleep/Wake Optimization:** Profile on hardware (`sleep_debug = yes`). **A power-key sleep still comes back after ~2 s** (a bare `printf mem` holds): the awake line in `banana/logs/sleep.log` now carries the kernel's `wake irq` (`/sys/power/pm_wakeup_irq`), the prep/whole-suspend timings, and a `sleep_skip` (`banana/bananad.conf`) to leave out one suspend step at a time -- `stop`, `ui`, `mute`, `hooks`, `sync` -- without rebuilding, to name the culprit. The PMIC RTC alarm is the ADSP's (`qcom,no-alarm`, as annotated on hamoa/glymur), so `sleep_check_hours`/`sleep_poweroff_percent` cannot fire -- the DTS comment now records that a plain DT flip is not the fix. bananad refuses to sleep a discharging battery at/under `sleep_floor_percent` (15) instead: the panel just goes dark, the SoC stays awake, and the 60 s poll still shuts it down cleanly. Then cut panel power-on & SD re-init latency (evaluate `MMC_CAP_RUNTIME_RESUME`), test keeping Wi-Fi module loaded across suspend, measure overnight standby drain.
- [x] **Wi-Fi Firmware:** the WCN3950 `ath10k` blobs (`ath10k/WCN3990/hw1.0/{firmware-5.bin,board-2.bin,wlanmdsp.mbn}`) and the WPSS firmware are in the board's `firmware/`, and `rcS` `modprobe ath10k_snoc` (verified against the driver's path in `linux-custom`). On-unit Wi-Fi association still to confirm.
- [ ] **Thermals & Fan:** Tune `pwm_fan` curve and profile thermals under sustained 10m+ N64/PSX load (`tools/rpc-thermals.sh`).
- [ ] **Audio handover (menu and game):** `run-retroarch` and banana-ui each wait "one beat" for the DSP to tear a frontend's graph down before reopening, because an open inside that window gets a half-built graph and the amps fail to start. Kernel patch `0063-…` now reports the `APM_CMD_GRAPH_CLOSE` result and logs a slow (>= 50 ms) close, so the window is measurable (`dmesg | grep -i q6apm`) and the two waits can be tuned or removed on the unit. The wait is now one knob: `audio_handoff_ms` in `banana/bananad.conf` (bananad publishes it to `/run/banana/audio-handoff-ms`; default 800, 0 disables), read by both the launchers (`audio-settle`) and banana-ui's `Sound`, so an experiment is a config change and a SIGHUP, not a script edit. A boot-time bug was found and fixed alongside it: bananad's codec sets used simple-mixer names (`"HPHL"`) through the raw CTL API, which needs `"HPHL Switch"`, so the "card enumerated after rcS's wait" fallback had silently never run (rcS's `amixer` copy hid it); `ctl_set()` now retries the `" Switch"` name and `audio_setup()` waits for a real DAPM control before the block.
- [ ] **PipeWire (Deferred/Optional):** Needs SoC UCM2 profile + `libudev-zero`/`udev-virtual` integration before replacing direct ALSA (see `docs/RPC-PORT.md`). *(UCM only helps a UCM-aware opener like PipeWire/ACP; without a sound server Banana keeps its own route writes -- see the audio handover item above.)*
